# Off-Policy Learning: IPS & Doubly-Robust

## 1. The Intuition

When booting up a new bandit system, you typically have to learn from historical data that was generated by a completely different policy (e.g., a rule-based surge pricing system or a purely random A/B test). This is known as **Off-Policy Learning**.

The problem is that this historical data is **biased**. If your old policy favored choosing the 1.2x price arm, your logs will be heavily saturated with 1.2x data, while lacking 1.5x data. If you train a model naively on this data, it will inherit that bias.

## 2. Inverse Propensity Scoring (IPS)

COBA uses Inverse Propensity Scoring (IPS) to un-bias the historical data. IPS weights every observation by the inverse of the probability (the **propensity**) that the logging policy chose that specific arm.

* **High Propensity (Common action)** -> Low weight. Since the logging policy chose this often, we down-weight its influence.
* **Low Propensity (Rare action)** -> High weight. The logging policy rarely chose this, so the few times it did provide highly valuable counterfactual information, which we up-weight.

### Doubly-Robust (DR) Correction

Pure IPS can suffer from extreme variance if propensities are very close to zero (resulting in massive weights). COBA also implements **Doubly-Robust (DR)** correction, which combines IPS with a reward prediction model to lower the variance while remaining unbiased.

### DR Runtime Contract

- `fit_from_logs(..., use_dr=True)` requires `reward_estimates`.
- `update_from_logs(..., use_dr=True)` also requires `reward_estimates` by default.
- If you intentionally want incremental updates to fallback to IPS when estimates are missing, configure:
  `IPSConfig(use_dr=True, allow_ips_fallback_when_dr_missing=True)`.

## 3. Example Usage

Here is a step-by-step example showing how to use `DoublyRobustUpdater` to bootstrap a `ClusterRouter` from biased historical logs.

```python
import numpy as np
from coba.offpolicy.ips import DoublyRobustUpdater, IPSConfig
from coba.routers.cluster_router import ClusterRouter
from coba.types import PolicyType

# 1. Initialize your empty router
router = ClusterRouter(
    arms=[1.0, 1.2, 1.5],
    n_clusters=3,
    policy=PolicyType.LIN_UCB,
    n_features=4
)

# 2. Prepare biased historical logs
n_samples = 1000
contexts = np.random.randn(n_samples, 4)
decisions = np.random.choice([1.0, 1.2, 1.5], size=n_samples, p=[0.7, 0.2, 0.1]) # Highly biased logging policy
rewards = np.random.rand(n_samples)
propensities = np.array([
    0.7 if d == 1.0 else 0.2 if d == 1.2 else 0.1 
    for d in decisions
])

# 3. Configure the IPS/DR updater
# clip_max prevents extreme weights from exploding the variance
config = IPSConfig(clip_min=1e-4, clip_max=10.0, use_dr=False)
updater = DoublyRobustUpdater(router, config)

# 4. Fit the router from logs (Offline Bootstrapping)
# This un-biases the data and trains the router all at once
updater.fit_from_logs(
    contexts=contexts,
    decisions=decisions,
    rewards=rewards,
    propensities=propensities
)

print(f"Router is now fitted and unbiased: {router.is_fitted}")

# 5. Incremental Daily Updates
# If you receive a new batch of logs tomorrow, use update_from_logs
# This updates the underlying models WITHOUT re-computing the KMeans clusters
new_contexts = np.random.randn(100, 4)
new_decisions = np.random.choice([1.0, 1.2, 1.5], size=100)
new_rewards = np.random.rand(100)
new_propensities = np.full(100, 0.33) # Maybe you switched to random traffic

updater.update_from_logs(
    contexts=new_contexts,
    decisions=new_decisions,
    rewards=new_rewards,
    propensities=new_propensities
)
```
